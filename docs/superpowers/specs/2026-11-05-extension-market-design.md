# 扩展市场设计（技能 / 连接器 / 插件 / 和 Claude 一起创建技能）

日期：2026-11-05。目标版本：1.7.0。

## 目标

让用户在手机 App 里浏览并安装 Claude 生态的扩展，不再只能手动粘贴地址；并能在对话中和 Claude 一起做出自己的技能。

已定方向：内容来源采用混合方式（精选目录打底，同时能接任意来源）；四块一次做完。

## 实测依据（2026-11-05）

以下都在隔离配置目录中实测，运行时为 Claude Code 2.1.318（SDK 0.3.318）和 2.1.112（旧版 Node 运行时）。环境是 Windows 和 WSL Ubuntu，**还没有在手机上跑过**。

| 事实 | 结果 | 对设计的影响 |
|---|---|---|
| `claude plugin marketplace add/install/enable/disable/uninstall/list --json` | 两个版本都可无交互运行；本地路径、URL、git-subdir、技能仓四种来源都装成功 | 直接调用官方 CLI，放弃原方案的“拆包” |
| `enabledPlugins` 写入 user 设置 | 新会话的 `init` 里出现 `插件名:技能名`；停用后消失 | 不需要 `plugins` 选项，`settingSources` 已含 `user` |
| `reloadPlugins()` | 新版立即生效；旧版滞后一次 | 新版热重载，旧版重启空闲会话（对话可续接） |
| `marketplace add owner/repo` | 走 SSH，无密钥时失败 | 一律转成 HTTPS 地址 |
| 官方市场克隆 | 约 12 秒，占 24 MB | 第一次打开插件页才下载，并显示进度 |
| `plugin list --available --json` | 新版 3925 条，含 3605 条 `anthropic-plugin-directory`；旧版 320 条 | 服务端搜索、分页、缓存 |
| 官方仓自带的 53 个插件 | 7 个带 hooks，13 个带 MCP | hooks 以 root 运行且不经过 `canUseTool`，安装时必须先看清内容 |
| MCP 注册表 `registry.modelcontextprotocol.io/v0.1/servers` | 公开可用，支持 `search` 和 `version=latest` | 连接器搜索直接用它；收录不代表安全 |
| 精选连接器地址探测 | 3 个返回 200，其余返回 401（需要授权） | 精选目录标明是否需要授权 |
| `claude mcp login`（新版） | 输出授权链接，回调到 `localhost`；需要真终端 | 用 pty 驱动；旧版用 `mcp__名字__authenticate` 工具走对话 |
| `skills` 查询选项 | 旧版 SDK 没有这个顶层选项；新版按文档只认列出的名字，插件技能要写全名 | 改为移动目录来停用，不再依赖过滤 |

开发中的端到端测试又查出两点，已在实现中处理：2.1.112 输出到管道时，进程退出会截断长 JSON，所以 CLI 输出改走临时文件；`mcp login --help` 在没有该命令的版本上也返回成功，所以要从 `mcp --help` 的命令列表判断。

未能实测：`mcp login` 的完整授权闭环（需要真实第三方账号）；登录后 SDK 会话能否复用令牌；已登录状态下的真实对话，包括插件技能被调用和 `create-skill` 全流程；手机 arm64 上的全部流程。这些列入真机验证。

## 架构

新增纯逻辑模块 `app/server/market.mjs`（解析、校验、合并，无副作用，有单元测试）。`server.mjs` 只负责调用 CLI 和对外接口。前端新增 `app/web/market.js`。

### 技能市场

- 精选目录 `app/catalog/skills.json`，条目指向官方仓 `anthropics/skills` 的子目录，安装时才从源头下载，不随 App 分发（部分官方技能的许可不允许再分发）。
- `installSkill` 改造：支持 `.../tree/<分支>/<子目录>` 地址和 `skills/*` 两层结构；安装前拒绝指向目录外的符号链接；id 严格校验（修复现有 `..` 可穿越的问题）。
- 停用技能改为把目录移到 `~/.claude/skills-disabled/`，不再传 `skills` 过滤。这样新旧运行时行为一致，插件技能也不会被误滤。启动时迁移一次，迁移规则与现有“已启用”列表一致。

### 连接器市场

- 精选目录 `app/catalog/connectors.json` 加注册表实时搜索。
- 注册表条目优先选远程地址；其次 npm（`npx -y`）或 PyPI（`uvx`），其余类型不支持。
- 需要密钥的连接器在添加时填写，保存在 `agent-mcp.json`，并扩展支持任意请求头和环境变量。
- 本地命令型连接器以 root 运行，添加前显示完整命令并要求确认。
- MCP 页面同时列出“来自 Claude 账号或插件”的连接器（只读）。状态为待授权时显示“授权”按钮。

### 插件市场

- 全部通过官方 CLI。首次打开时注册两个官方市场。可添加任意 HTTPS 市场仓库。
- **两步安装：** 下载后立即停用 → 读取安装目录，列出技能、命令、子代理、hooks 和 MCP → 用户确认后才启用。安装和停用之间用闸门挡住新会话启动，避免 hooks 被加载。
- 非官方市场的插件和带 hooks 或本地命令的插件给出明确警告。
- 官方目录里的插件作者可能是第三方，界面不声称“已审核”或“安全”。

### 和 Claude 一起创建技能

- 新增内置技能 `create-skill`（自行编写，面向手机场景）。官方 `skill-creator` 依赖较重（225 KB，评测要反复调用 `claude -p`），可从市场另行安装，不内置。
- 流程：入口按钮开新对话 → Claude 逐个提问 → 草稿写入 `~/.claude/skill-drafts/<id>/` → 回合结束时服务端发现草稿并提示 → 用户预览后“保存并启用”或丢弃。
- 只有用户点保存才进入技能目录，保存时校验 frontmatter 和符号链接。

### 界面

- 设置“助手”分组最上方加“扩展市场”；`/market` 命令；技能页和连接器页互相可达。
- 沿用现有主题和样式变量。所有第三方文字都转义后再显示。

## 错误处理

- 网络失败：提示检查代理；CLI 继承已配置的代理；设置 `GIT_TERMINAL_PROMPT=0` 防止私有仓库挂起。
- 安装中途失败：不留半成品（技能先放临时目录，校验通过后才落地）。
- 所有递归删除只作用于校验过 id 的子目录，绝不接受外部路径。

## 测试

- 单元测试：`tests/market.test.mjs`（`node --test`）。
- 端到端：在 WSL 用隔离 HOME 启动真实服务，通过接口和浏览器走完四条流程。
- 真机：手机连接后验证各类型安装、会话生效、OAuth 授权、自动更新后的迁移。

## 发布

在 `feat/extension-market` 分支开发。推送到 `main` 会触发自动发版，手机可能静默更新，因此合并前要先得到确认，并尽量先完成真机验证。
