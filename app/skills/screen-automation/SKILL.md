# 屏幕自动化（droid）

## 后台屏幕

`droid app 包名` 默认把应用开在一块**用户看不见的后台屏幕**上：用户照常用自己的手机，你在后台操作。之后的 `ui`、`shot`、`tap`、`text`、`key` 等命令都作用在这块后台屏幕上，直到 `droid bg stop`。

- 用户想看你在做什么、或想自己接着操作时：`droid show`，把应用移到用户屏幕上。之后不要在用户屏幕上继续操作，除非用户同意。
- 用户正在前台使用的应用，droid 不会把它拿到后台，会报错提示；先问用户，同意后用 `droid app 包名 --front` 在用户屏幕上操作。
- 后台屏幕没有桌面、最近任务、通知栏：换应用直接 `droid app`，`home`/`recent` 键不可用。
- 应用在后台黑屏或打不开时（少数游戏、视频、银行类应用），告诉用户，征得同意后再用 `--front`。

### 在后台屏幕上打字

- **后台屏幕永远不会弹出键盘，这是正常的**，不要等键盘，也不要因为没键盘就认为打不了字。输入框显示没被选中（没有 focused）也没关系。
- 直接对准输入框打字：先 `droid ui` 找到输入框的编号（标着 `[edit]`），再 `droid text "内容" --id 编号`。droid 会先点它，再把字直接填进去。
- 也可以按坐标：`droid text "内容" --at X Y`。
- `droid text` 会核对字是否真的进去了，并说明用的哪种方式。失败时会列出屏幕上所有输入框的位置，换一个再试。
- 聊天应用（微信等）底部如果是「按住 说话」，说明在语音模式：先点旁边的键盘图标切换到文字输入，再打字。
- 打完字，再点「发送」按钮（发消息前按规则先确认）。

## 基本循环

1. **观察**：`droid ui` —— 列出可交互控件（编号、文字、中心坐标）。比截图更准、更快，优先用它。
2. **决策**：找到目标控件的编号或文字。
3. **动作**：`droid tap-id N` / `droid tap-text 文字` / `droid tap X Y`。
4. **再观察**：动作后重新 `droid ui`（或 `droid wait-text 期望出现的文字 --timeout 8`）确认结果，**不要连续盲点**。

`droid ui` 找不到目标（游戏、WebView、自绘界面）时，改用截图：`droid shot --grid`，然后用 Read 查看 `/tmp/droid/shot.png`。截图默认 0.5 倍，**设备坐标 = 图上坐标 ÷ 0.5**。

## 常用动作

| 需求 | 命令 |
|---|---|
| 打开应用 | `droid app <包名>`（不知道包名：`droid apps 关键词`） |
| 当前前台 | `droid top` |
| 后台屏幕状态 | `droid bg`；给用户看：`droid show`；关掉：`droid bg stop` |
| 输入文字 | 先点中输入框，再 `droid text "内容"`（中文、表情都可以；不用键盘，直接填进去，输出会说明用的哪种方式） |
| 按键 | `droid key back` / `enter` / `del`（`home` / `recent` 只在用户屏幕上有） |
| 滑动 | `droid swipe X1 Y1 X2 Y2 300`；向下翻一屏：从屏幕 75% 高度滑到 25% |
| 长按 | `droid longpress X Y 800` |
| 点亮屏幕 | `droid wake` |

## 可靠性技巧

- 列表里找东西：滑一屏 → `droid ui` → 没找到再滑，最多滑 N 次后告诉用户没找到。
- 有加载动画时用 `droid wait-text`，不要用固定 `sleep` 猜。
- 弹窗（权限、广告、更新提示）会挡住目标：先处理弹窗再继续。
- 重复任务（比如批量点赞、逐条处理）先做一条，确认流程正确再批量执行，并在中途报告进度。
