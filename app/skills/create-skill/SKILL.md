# 创建技能

和用户一起把一件反复要做的事写成技能。用户大多不懂技术，用大白话交流，不要讲 frontmatter、YAML 这些词。

## 第一步：弄清要做什么

一次只问一个问题，能从对话里看出来的就不要再问。需要弄清：

1. 这个技能要帮你做什么？举一个最近的真实例子。
2. 你通常会怎么说，来让我用它？这决定它什么时候被触发。
3. 做完以后，你希望看到什么样的结果？
4. 有没有绝对不能做的事？比如不能删文件、不能联网。

如果这段对话里已经做过这件事，先总结刚才的步骤，请用户确认哪些要保留，不要从头问起。

## 第二步：写草稿

只写到草稿目录 `~/.claude/skill-drafts/<id>/SKILL.md`，**不要写进 `~/.claude/skills/`**。用户在 App 里确认后，App 才会把它保存为正式技能。

`<id>` 用小写英文和连字符，描述这件事，例如 `weekly-report`。文件格式固定：

```markdown
---
name: <和目录名完全相同的 id>
description: <做什么，以及用户说什么话时应该使用。写具体，这是决定它会不会被用上的唯一依据>
---

# <中文标题>

<正文>
```

正文的写法：

- 写给以后的你看：按顺序列出步骤，每步写清用什么命令或工具、怎么判断成功。
- 写明为什么这样做，遇到没预料到的情况时才知道怎么变通。
- 把用户说的禁止事项原样写进去。
- 能短则短，一般不超过 100 行。参考内容太多时，放到同目录的其他文件里，并写明什么时候读。
- 不要写入密码、令牌等密钥。需要时让用户在运行时提供。
- 这台手机是 root 环境，`/data`、`/system`、`/sdcard` 是真实分区。技能里不要写递归删除、改权限这类命令，除非用户明确要求，并且写明执行前要确认。

## 第三步：确认

写完后，用几句话告诉用户：

- 它会在什么时候被用上
- 它会做哪几步
- App 里已经出现草稿提示，点开可以预览，然后选择「保存并启用」或「丢弃」

用户想改，就直接修改草稿文件，改完再说一声。不要自己把草稿移到技能目录。

## 第四步：试用

用户保存后，建议在新对话里用第二步想到的说法试一次。如果没有被触发，多半是 description 不够具体，帮用户改好。
